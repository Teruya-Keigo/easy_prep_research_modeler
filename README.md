# PReP Research Modeler

PRePの成果物中心記法で、研究プロセスやテスト設計プロセスを視覚的に記述するブラウザ完結型エディタです。v1.2では、複数プロセスを結ぶ「鳥瞰図」と、1プロセスをアクター横レーン×サブプロセス縦列で編集する「プロセス詳細」を分離しました。v1.2.1では両キャンバスへタッチパッドの二本指パンを、v1.3.0ではサブプロセス範囲ボックスの幅・高さのリサイズと保存を追加しました。

バックエンドやアカウントは使用しません。モデルはブラウザの `localStorage` と、利用者がダウンロードする `.prep.json` ファイルで管理します。新規保存形式は `schemaVersion: "1.3.0"` です。

## v1.3.0の主な機能

- トップレベルプロセスと外部プロセスを二重丸で表示する鳥瞰図
- `PrepProcess.parentProcessId` による再帰的なサブプロセス階層
- 1画面につき1プロセスを扱うプロセス詳細
- アクター別の横レーンと、直下サブプロセス別の縦列
- サブプロセス範囲ボックスごとの幅・高さ変更と自動高さ
- 交点セルへの成果物配置と、1人の主責任アクターの割り当て
- 中間、最終、マイルストーン、無実体の4種類の成果物
- 上、右上、右、右下、下、左下、左、左上の8方向接続点
- PRePの入力・同期関係と、6種類の研究用意味ラベル
- 鳥瞰図で管理するプロセス間引継ぎ
- モデル検証、保証連鎖、変更影響分析、リスク表示
- Undo / Redo、ズーム、マウスドラッグ／タッチパッド二本指によるパン、全体表示、鳥瞰図の自動整列
- JSON保存・読込、自動保存、PNG / SVG画像出力
- v1.0.0 / v1.1.0 / v1.2.0保存データの移行読込
- 空モデル、制約付き多ラベル分類、コーヒープロセスのテンプレート

## 起動方法

### 必要環境

- Node.js 20.19以降、または22.12以降
- npm
- 最新版のChrome系ブラウザを推奨
- Safariでは基本編集、JSON保存・読込、Macのトラックパッドによる二本指パンとピンチズームを確認対象とします

### 開発サーバー

```bash
npm ci
npm run dev
```

ブラウザで <http://127.0.0.1:4173> を開きます。

### 本番ビルドの確認

```bash
npm run build
npm run preview
```

`dist/` に静的ファイルが生成されます。バックエンドを必要としないため、静的サイトとして配信できます。

## 操作方法

### 1. モデルを開始する

初回起動時は空モデルが開きます。左側の「テンプレート」から次の例へ切り替えることもできます。

- 空のモデル
- 制約付き多ラベル分類：アクターレーン、サブプロセス列、8成果物を持つ研究用テンプレート
- コーヒーを淹れる：鳥瞰図、プロセス間引継ぎ、プロセス詳細を確認できる小さな例

編集中にテンプレートを切り替えると、現在のモデルを置き換えるか確認されます。上部の「新規」も同様に新しいモデルを開始します。

### 2. 鳥瞰図を編集する

鳥瞰図には、`parentProcessId` のないトップレベルプロセスと外部プロセスだけが表示されます。サブプロセスや成果物は表示されません。

- 左の「トップレベルプロセス」または「外部プロセス」をクリックすると既定位置へ追加できます。キャンバスへドラッグすると任意位置へ追加できます。
- プロセスの二重丸をドラッグして移動します。
- トップレベルプロセスをダブルクリックするか、フォーカスして Enter を押すと詳細を開きます。
- 上部のプロセス選択、またはプロパティの「このプロセスを開く」からも詳細へ移動できます。
- 「自動整列」は `processHandoffs` の向きを使って鳥瞰図だけを整列します。詳細グリッドにはDagreを使用しません。
- 「全体表示」で現在の鳥瞰図を画面へ収めます。

詳細から鳥瞰図へ戻る場合は上部の「鳥瞰図」を押します。鳥瞰図と各プロセス詳細は同じキャンバスへ混在しません。

### 3. プロセス詳細を作る

プロセス詳細は、選択中の1プロセスを `activeProcessId` として開きます。表示対象はそのプロセス自身、直下のサブプロセス、参加アクター、所属成果物、画面内の成果物間関係だけです。

1. 左の「アクター」を追加して横レーンを作ります。
2. 左の「サブプロセス」を追加して縦列を作ります。
3. 左の成果物をクリックするか、アクター×サブプロセスの交点セルへドラッグします。
4. 成果物を選び、右の「プロパティ」で名称、種類、状態、属性、責任アクター、所属サブプロセス、リスクなどを編集します。

アクターとサブプロセスの両方がなければ交点セルを作れません。成果物をクリックして追加した場合は先頭のセルへ置かれます。選択中プロセス自身に直接属する既存成果物は、保存上のプロセスを増やさない仮想的な「未分類」列へ表示されます。

成果物を別セルへ移動すると、配置と責任が次のように更新されます。

| 移動 | 更新されるデータ |
|---|---|
| 同じ列の別レーン | `responsibleActorId` |
| 同じレーンの別列 | `processId` |
| 別レーン・別列 | `responsibleActorId` と `processId` |
| 同じセル内 | セル左上からの相対座標 |

アクターのレーン見出しを選ぶと下辺にリサイズハンドルが表示され、ドラッグでレーン高さを変更できます。右パネルの数値入力でも高さを編集できます。レーンはキャンバス全幅に伸びるため、幅は個別に変更しません。高さは最小160pxで、成果物がある場合は外周＋24pxの余白を残して縮小が止まります。後続レーンと `auto` 高さのサブプロセス範囲は追従しますが、成果物の配置・所属や手動設定した列高さは変わりません。手動高さの列から後続レーンの成果物がはみ出す拡大も制限します。1回のドラッグは1回のUndo操作です。

右パネルではアクターの名称、役割、レーン順序も編集できます。責任成果物を持つアクターの削除時は、別アクターへの一括移管が必要です。サブプロセスの列順序・幅・手動高さと親プロセスも保存されます。親には自分自身や自分の子孫を選べません。

サブプロセスの列見出しを選ぶと、範囲ボックスの右辺・下辺・右下角にリサイズハンドルが表示されます。右辺は幅、下辺は高さ、右下角は両方を変更します。右のプロパティパネルでも幅と高さを数値入力できます。新規サブプロセスは幅360px、高さは全アクターレーンの合計高へ追従する `auto` です。高さを初めて変更すると手動高さに切り替わり、「高さを自動に戻す」または範囲ボックスのダブルクリックで `auto` に戻せます。

幅の下限は260px、手動高さの下限は160pxです。成果物がある場合は、その外周から24pxの余白を確保できる位置で縮小が止まります。幅を変更すると後続列の位置が変わりますが、高さは列ごとに独立しており、成果物の位置・大きさ・責任アクター・所属サブプロセスはリサイズで変わりません。1回のドラッグは1回のUndo操作として扱われます。

深い階層を編集するときは、列見出しの「開く」、または右パネルの「このプロセスを開く」で対象サブプロセスへ移動します。孫以下のプロセスを親の詳細画面へ重ねて表示しません。

### 4. 成果物間の関係を作る

成果物には次の8個の接続点があります。

| ID | 位置 | ID | 位置 |
|---|---|---|---|
| `n` | 上 | `ne` | 右上 |
| `e` | 右 | `se` | 右下 |
| `s` | 下 | `sw` | 左下 |
| `w` | 左 | `nw` | 左上 |

始点の接続点から、同じ詳細画面に見えている別の成果物の接続点へドラッグします。表示されたダイアログで次を設定します。

1. PReP標準関係：入力関係、または同期関係
2. 研究用意味ラベル：なし、`derives-from`、`justifies`、`mitigates`、`approves`、`monitors`、`requires-revalidation-of`
3. 始点・終点の接続点
4. 説明

入力関係は実線の有向矢印、同期関係は点線の双方向矢印です。研究用意味ラベルは線種とは独立した `semanticType` として保存されます。作成後も関係を選択し、右パネルから線種、意味ラベル、両端の接続点、説明、リスクを変更できます。

別のトップレベルプロセスへ詳細画面をまたぐ長い成果物線は作りません。その連携は鳥瞰図のプロセス間引継ぎとして表します。

### 5. プロセス間引継ぎを作る

鳥瞰図で2つのトップレベルプロセスを選択して左の「プロセス間引継ぎ」を押すか、一方の8方向接続点から他方へドラッグします。引継ぎダイアログでは次を設定します。

- 引継ぎ元と引継ぎ先
- 引継ぎ元の最終成果物（0件以上）
- 受け側の外部入力成果物（0件以上）
- 入力関係または同期関係
- 始点・終点の接続点
- 説明

引継ぎは成果物間の `PrepRelation` ではなく `ProcessHandoff` として保存されます。成果物がまだない段階でも引継ぎを先に作れますが、対応成果物がない状態は検証警告の対象です。

### 6. 選択、移動、表示

- ノードのドラッグ：移動
- タッチパッドの二本指ドラッグ（縦・横・斜め）：キャンバスのパン
- マウスホイール：縦方向のパン
- ピンチ、または Ctrl / Command + スクロール：ズーム
- 中ボタンまたは右ボタンのドラッグ：パン
- Space + ドラッグ：パン
- Shift + ドラッグ：範囲選択
- Ctrl / Command + クリック：複数選択
- Ctrl / Command + Z：元に戻す
- Ctrl / Command + Shift + Z：やり直す
- 右パネルの削除ボタン：選択要素を削除

ウィンドウが編集画面より小さい場合は、キャンバス外でブラウザの縦横スクロールバーを使い、左右パネルと画面下部へ移動できます。ポインタがキャンバス上にある間のスクロール入力はキャンバス操作に使われ、ページ本体はスクロールしません。パン後の `x`、`y`、ズーム倍率はモデルに保存されます。

プロセス詳細の「自動整列」は固定グリッドを変更しません。レーン順序、列順序、保存済みサイズからセル矩形を計算し、成果物はセル内だけを移動します。

### 7. 検証と分析

上部の「検証」を押すと、右側の検証タブにエラー、警告、対象要素を表示します。項目を押すと該当箇所へ移動します。プロセス階層の循環、存在しない参照、責任アクター不足、重複レーン、接続点、引継ぎ成果物に加え、サブプロセス範囲ボックスの幅・手動高さの不正値（`E023`）も検査します。

プロセス詳細で成果物を1件選ぶと、次の分析を実行できます。

- 保証連鎖：選択成果物から上流・下流へ到達できる成果物と関係を強調
- 変更影響：`requires-revalidation-of` による明示的影響と、入力関係による推定影響を区別
- リスク表示：中・高リスクの成果物と関係を強調

保証連鎖と変更影響は鳥瞰図では無効です。

### 8. JSONと画像を出力する

- 「JSON保存」：`<モデル名>.prep.json` をダウンロード
- 「JSON読込」：`.json` または `.prep.json` を検証後に読込
- 「PNG出力」「SVG出力」：現在のモードだけを画像化

プロセス詳細では現在開いている1プロセス、鳥瞰図では鳥瞰図全体が画像へ出力されます。

## 保存形式

### 自動保存

変更後、およそ1.2秒のデバウンスを経てモデル全体をブラウザの `localStorage` へ保存します。v1.3の保存キーは `prep-research-modeler:model:1.3.0` です。同じブラウザ・同じオリジンで再度開くと復元します。

ブラウザデータを削除した場合、シークレットモードを終了した場合、または別のオリジンで開いた場合は自動保存データを共有できません。長期保管や受け渡しにはJSON保存を使用してください。

### v1.3 JSON

ファイルはUTF-8、2スペースインデントで保存され、`schemaVersion: "1.3.0"` を必須とします。主な構造は次のとおりです。

| フィールド | 内容 |
|---|---|
| `metadata` | モデルID、モデル名、作成日時、更新日時 |
| `system` | システム名、ゴール、フェーズ、作成者 |
| `processes` | トップレベル／サブプロセス、親ID、主担当、技術、リソース |
| `actors` | アクターと移行用の未割当情報 |
| `processActorLanes` | 詳細画面ごとのアクター、役割、順序、高さ |
| `artifacts` | 4種類の成果物、所属、責任アクター、状態、属性、リスク |
| `externalProcesses` | 鳥瞰図に表示するモデル外部の接続先 |
| `relations` | 成果物間の始点・終点、8方向接続点、`prepType`、`semanticType`、リスク |
| `processHandoffs` | トップレベルプロセス間の向き、対応成果物、接続点、線種 |
| `layout.processViews` | プロセス別の列順序・幅・任意の手動高さ、成果物のセル内相対座標、ビューポート |
| `layout.overview` | トップレベル／外部プロセスの鳥瞰図座標とビューポート |
| `layout.lastView` | 最後に開いたモードとプロセス |

`layout.processViews[].subprocessColumns[].height` を省略すると `auto` 高さとなり、全アクターレーンの合計高に追従します。数値を保存した場合は、その列だけ手動高さになります。`layout.nodes` と `layout.viewport` はv1.0/v1.1コードとの移行期互換投影で、正規のv1.3 JSON作成側には必須ではありません。React Flow固有の選択状態や描画データは保存モデルの正にしません。

構文またはスキーマが不正なファイルは現在のモデルへ適用せず、検証タブに詳細を表示します。将来版が追加した未知のフィールドは読込時に無視します。

### v1.0.0 / v1.1.0 / v1.2.0からの移行

「JSON読込」と起動時の自動保存復元では、v1.0.0、v1.1.0、v1.2.0を検証してからv1.3.0へ移行します。旧 `localStorage` キー `prep-research-modeler:model:1.2.0`、`prep-research-modeler:model:1.1.0`、`prep-research-modeler:model:1.0.0` も探索し、読込成功後はv1.3キーへ保存します。

移行時の主な変換は次のとおりです。

- v1.0のプロセスはすべてトップレベルとして扱い、v1.1の `parentProcessId` は保持
- 旧 `responsibleActor` 文字列を同名ごとに1件の `PrepActor` へ統合し、成果物を `responsibleActorId` で参照
- 責任主体が空の旧成果物を仮アクター「未割当」へ配置し、修正対象として検証
- 旧プロセス座標を鳥瞰図座標へ、旧成果物座標を該当セル内の相対座標へ変換
- 直下サブプロセスの旧x座標順を列順序へ、旧責任主体の出現順をレーン順序へ変換
- 旧関係の両端を `sourceAnchor: "auto"` / `targetAnchor: "auto"` として保持
- 旧 `nextProcessName` が同名のトップレベルプロセス1件へ解決できる場合、最終成果物を `ProcessHandoff` へ変換
- 解決できない次工程名を `legacyNextProcessName` に残し、鳥瞰図で対応付けるまで警告
- v1.2のサブプロセス列は保存済みの幅と順序を保ち、高さ未指定の `auto` として読み込む

移行はメモリ上で行い、明示的にJSON保存すると `1.3.0` 形式になります。元のファイル自体を上書きしません。

## 設計判断

- 詳細編集を「1画面＝1プロセス」とし、トップレベルプロセス間の構造は鳥瞰図へ分離しました。
- サブプロセス専用の重複型は作らず、`PrepProcess.parentProcessId` で任意深度の階層を表します。
- アクター横レーンとサブプロセス縦列は背景装飾ではなく、成果物の `responsibleActorId` と `processId` に対応する制約です。
- 詳細グリッドはレーン・列・セルから決定的に計算します。Dagreは `ProcessHandoff` を使う鳥瞰図の自動整列だけに使用します。
- 列ごとの高さが違ってもアクターレーンは共通の横帯として維持し、範囲ボックスとレーンの交差領域だけを配置可能セルにします。リサイズでは成果物の所属や責任を変更しません。
- 成果物間の `PrepRelation` とトップレベルプロセス間の `ProcessHandoff` を分離し、詳細画面をまたぐ長い線を作りません。
- PReP標準の線種を `prepType`、研究用の意味を `semanticType` として分離します。
- 保存データの正を `PrepModelFile` とし、UIライブラリの内部表現へ直接依存させません。
- 二本指パンは React Flow の `panOnScroll`、`panOnScrollMode="free"`、`zoomOnScroll`、`zoomOnPinch`、`preventScrolling` で実現し、独自の `wheel` ハンドラは追加していません。
- バックエンドを設けず、保存処理をリポジトリのインターフェース越しに分離しています。

## 技術構成

| 用途 | 技術 |
|---|---|
| UI・ビルド | React 19、TypeScript、Vite |
| グラフ編集 | `@xyflow/react` |
| 状態管理 | Zustand |
| スキーマ検証 | Zod |
| プロセス詳細レイアウト | 独自のアクター×サブプロセス固定グリッド |
| 鳥瞰図の自動整列 | `@dagrejs/dagre` |
| 画像出力 | `html-to-image` |
| アイコン | `lucide-react` |
| 単体・DOMテスト | Vitest、React Testing Library |
| E2E | Playwright |

主要な責務は次のように分離しています。

```text
src/
├── domain/       保存モデル、移行、階層、グリッド、検証、分析
├── store/        モデル操作、選択、履歴、表示状態
├── editor/       鳥瞰図／詳細キャンバス、ノード、関係の描画
├── components/   ツールバー、パレット、プロパティ、結果パネル
├── services/     自動保存、JSON、画像出力、鳥瞰図の自動整列
└── templates/    空モデルとサンプルモデル
```

## テスト方法

初回のみ、PlaywrightのChromiumをインストールします。

```bash
npx playwright install chromium
```

用途に応じて次を実行してください。

```bash
# TypeScriptの型検査
npm run typecheck

# Vitestの単体・コンポーネントテスト
npm test

# 本番ビルド
npm run build

# Playwright E2E
npm run test:e2e
```
